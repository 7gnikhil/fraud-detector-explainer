0 The raw message

Exactly as the user received it — link, amount, urgency and all. This is the only input the model ever gets: text.

1 Preprocessing — clean & anonymize

[PHONE][OTP] [URL][ACCOUNT] [UPI][EMAIL]

Unicode is normalized (NFC), native Telugu/Devanagari digits become ASCII digits, and every private identifier is replaced by a placeholder — the identical function runs in training and in prediction, so the model never sees a real phone number or OTP, and training can’t drift from serving.

2 Tokenization — WordPiece

MuRIL’s WordPiece tokenizer splits text into sub-word pieces from a 197,285-token vocabulary built for Indian languages, adds [CLS] / [SEP], and pads/truncates to 128 tokens. (Display simplified: pieces shown per word.)

3 Language detection

The script does most of the work: Telugu block (అ–ఱ), Devanagari (अ–ह) or Latin — with word lists catching Romanized Telugu and Hinglish. The detected language chooses which classifier head scores the message: there is one head per language, never a single mixed model.

4 MuRIL embedding — the neural network

768 numbers — one per hidden dimension (strip compressed for display)

MuRIL (Google’s Multilingual Representations for Indian Languages) reads the tokens through 12 transformer layers and we average the token vectors (mean pooling) into one 768-number meaning fingerprint. The network is frozen — pre-trained by Google, never fine-tuned by us — so it can’t overfit our small dataset. In the extension this runs as a 239 MB int8 ONNX model, on-device.

5 Lexical + structured features

Alongside the embedding, the message is hashed into word + character n-gram features (2¹⁴ + 2¹⁵ buckets — the lexical arm, and the one computing this page’s live score) and 30 hand-built signals are measured: links, OTP pressure, prize lures, block threats, digit runs… The chips above that lit up are the signals actually present in your message.

6 The classifier — stacked logistic regression

0% — safethreshold100% — fraud
—

A per-language logistic regression stacks the three views — MuRIL embedding + lexical hashes + structured signals — into one fraud probability. Each language has its own decision threshold, and a ±8-point uncertainty band around it: inside the band the honest answer is “uncertain — needs review”, never a forced guess.

🗄️ The dataset — real messages, balanced by hand

Collected from real Indian fraud reports and genuine notifications — government & TRAI advisories, Truecaller reports, consumer-complaint posts, news quotes — every row checked for duplicates, fraud kept only when a real scam cue is present (prize lure, block/KYC threat, OTP request, upfront fee, impersonation + payment demand). Awareness messages that merely describe a scam are labelled genuine.

1 : 1fraud : genuine balance, per language — the model can’t win by guessing one class

🏋️ How it was trained

1Split first

5-fold Stratified Group cross-validation per language — five 80:20 rounds, class ratio held at 50:50, skeletons grouped.

2Augment after the split

Paraphrase augmentation touches training folds only. The test fold stays 100% real.

3Extract

Frozen MuRIL → 768-dim vectors; hashed lexical features; 30 structured signals; scalers fit on train folds only.

4Fit one head per language

Logistic regression per language; synthetic rows weigh 0.5; class weights instead of SMOTE.

5Tune thresholds honestly

Per-language thresholds + ±0.08 uncertainty band, chosen on out-of-fold scores — then frozen before the challenge test.

Seven classifier families raced for the head (logistic regression, linear & RBF SVM, random forest, XGBoost, MLP, kNN) — logistic regression kept the best precision/simplicity balance per language. An earlier fine-tuned model once scored a perfect 1.00 — and turned out to be leaking; it was discarded. Near-perfect scores are treated as a leakage alarm here, not a result.

🚀 After training — how the model runs

📄In the page

Select text, right-click, drag it onto the 🛡️ button — or use the popup. The panel you see on this website is the same interface.

⚙️Offscreen engine room

The extension runs ONNX Runtime Web in a hidden offscreen document: int8-quantized MuRIL (239 MB), the lexical model and the heads — all on the user’s device.

✍️Corrections teach it

“It’s fraud / It’s safe” adjusts a small local adapter instantly. Sharing an anonymized copy to improve the shared model is opt-in, default OFF.

🔁Retrain pipeline

Shared corrections land in a private inbox → scheduled retraining builds a challenger → it ships only if it beats the champion on fixed evaluation gates. Model updates are a small config file — the 239 MB encoder is never re-downloaded.

⚠️ Honest limitations

  • It classifies; it cannot block. It cannot stop a message, call or payment, freeze money, or file a report. If money was lost: call 1930, report at cybercrime.gov.in, inform your bank.
  • A verdict is evidence, not a guarantee. “Looks safe” is not proof of safety; “fraud” is not proof of a crime.
  • Text only. No inbox scanning, no WhatsApp/calls, no screenshots, QR codes, voice notes, or link destinations.
  • Three languages only — Telugu, Hindi, English (incl. Hinglish / Romanized Telugu).
  • New scams can slip through until corrections retrain the model; borderline scores return UNCERTAIN by design.
  • Training data is thinner than we want, above all genuine Hindi/Telugu messages — field accuracy will differ from test numbers.
  • Not a government body. Not legal advice. Official routes: 1930 and cybercrime.gov.in.
